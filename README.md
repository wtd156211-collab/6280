# 背压与丢弃策略（从 0 实现）

起始环境里只有本说明、`samples/**` 与 `.gitignore`：引擎、页面、测试都新写。Python 3.13、只用标准库；
交付物是引擎（库 + 入口 `backpressure.py`）和它生成的 `backpressure.html`（单文件、双击即开），测试用
unittest。

## 一、范围

做：一个有界缓冲的消费端。它读一份注入的到达时序脚本（每条事件的到达时刻、等级、来源、字节、消费耗时都写
死），按水位线决定接纳还是丢弃，按等级与新老挑牺牲品，按先进先出消费，输出逐行可核的轨迹，再画成能复盘
那次内存打爆的页面。

不做：真实消息队列与网络重试、读系统时钟或依赖真实调度、线程与协程、上游侧缓存与流控（上游不动）、持久化
与告警、第三方依赖与构建步骤；`samples/**` 只读，期望文件不是输入。

## 二、事件的表达格式

时刻、字节、耗时都是整数（毫秒 / 字节）。脚本 `samples/scripts/<名>.txt` 里 `#` 开头是注释、空行忽略，
第一条有效行是头，之后一行一条事件：

```
H|名=01-steady|预算=8192|容量=64|高水位=6144|低水位=2048
E|80|0|edge-a|256|30
E|80|1|edge-b|320|35
E|81|2|edge-c|512|40
E|81|3|edge-d|1024|50
```

头里五个字段缺一不可；事件行是 `E|到达时刻|等级|来源|字节|耗时`。等级四档写死：0、1 普通，2 重要，
3 关键；来源是不含 `|` 的非空串。

约束：`0 < 低水位 < 高水位 ≤ 预算`、`容量 ≥ 1`、`1 ≤ 字节 ≤ 预算`、耗时 `≥ 1`、至少一条事件、到达时刻
`≥ 0` 且非降。关键事件零丢失也做得到：脚本保证全部等级 3 事件的字节和 ≤ 预算；不成立即输入不可用。

## 三、水位线口径（高水位、低水位、滞回）

- 占用＝队列里所有事件的字节和；条数＝队列里的条数。
- 进入背压看高水位、退出看低水位，中间是滞回带：占用在带里上下不会反复进出。
- 只在占用变化后（入队、出队、驱逐各算一次）查一遍：占用 ≥ 高水位且不在背压 → 进入；≤ 低水位且
  在背压 → 退出。
- 背压只改本端接纳口径，不改上游；背压态下等级 0/1 的到达一律拒收、不腾地方，等级 2/3 照常走第四节。

## 四、丢弃策略（按等级与新旧、高等级兜底）

一条到达这样处理：

1. 背压态且等级 ≤ 1 → 拒收，结束。
2. 否则若 `占用 + 本条字节 > 预算` 或 `条数 + 1 > 容量`，就要腾地方：只要还放不下，就丢队里「等级最低、
   同级最晚入队」的一条。
3. 腾完仍放不下 → 本条拒收；放得下 → 入队。

可驱逐的只有等级 0/1/2，等级 3 永不牺牲；驱逐只动等级比自己低的项，同级或更高的留着，新来的自己走。
拒收＝没进过队列，驱逐＝进过又被丢出来。

## 五、内存预算与调度注入

- 硬约束：任意时刻 `占用 ≤ 预算` 且 `条数 ≤ 容量`，把刚入队那条算进去也要成立。
- 单消费者：空闲时取队首，取走即开始处理（出队时刻），处理到「时刻 + 耗时」才算完。
- 时间与调度全靠注入：不读系统时钟、不起线程、不用定时器，时刻只来自脚本；同一时刻先
  结算全部到达（按脚本次序，内部先驱逐后入队），再做出队（至多一条）。
- 截止取最后一条出队处理完毕的时刻；吞吐 = 出队条数 × 1000 / 截止（每秒）。

## 六、输入输出与文件格式

文件一律 UTF-8 无 BOM、LF 换行、末行有换行。

6.1 轨迹（`run` 的输出），字段间一个 `|`：

```
H|<名>|预算=<字节>|容量=<条>|高水位=<字节>|低水位=<字节>|到达=<条数>
I|80|0|edge-a|256
O|80|0|edge-a|256|30
D|536|0|edge-p|64|拒收
P|5040|占用=12672|条数=18
R|5700|占用=3072|条数=1
T|到达=<n>|入队=<n>|出队=<n>|拒收=<n>|驱逐=<n>|关键丢失=<n>|内存峰值=<字节>|峰值条数=<条>|背压=<次>|截止=<毫秒>|吞吐=<x.3f>
```

`I` 入队、`O` 取走开始处理、`D` 丢弃（原因 `拒收`/`驱逐`）、`P`/`R` 进入与退出背压。行按时刻升序，同一
时刻按第五节的次序。恒等式：`到达 = 入队 + 拒收`、`入队 = 出队 + 驱逐`、`关键丢失 = 0`、
`内存峰值 ≤ 预算`、`峰值条数 ≤ 容量`、`背压 = P 行条数 = R 行条数`。

6.2 门槛 `samples/expected-metrics.txt`：一行一个脚本，六行，次序同样例编号。

```
01-steady|内存峰值<=576|关键丢失<=0|吞吐>=24.806
```

6.3 命令行（仓库根目录执行；`backpressure.py` 既是库也是入口，公开接口自定，写进模块 docstring）：

```
python backpressure.py run <脚本文件> <轨迹文件>
python backpressure.py report <轨迹文件> <页面文件>
```

诊断走 stderr；退出码 0 跑完，1 输入不可用（此时不写输出文件）。

6.4 页面 `backpressure.html`：`report` 只读轨迹、不重算。单文件 HTML、样式内联、无脚本、无外部引用、双击
即开，两遍逐字节相同；内嵌 `<pre id="trace">` 与轨迹逐字节相同（去末尾换行，`&`→`&amp;`、
`<`→`&lt;`、`>`→`&gt;`）。页面上要有：占用随时间的内联 SVG 台阶曲线（`data-kind="curve"`，横轴
`0..截止`、纵轴 `0..预算`）；高、低水位两条虚线（`data-kind="high"`/`"low"`）；每段背压一个矩形
（`data-kind="backpressure"`）；每条 `D` 行一项丢弃记录（`data-kind="drop"`）。

## 七、性能与验收口径

规模：`06-scale` 有 17600 条事件，其余脚本 232–1500 条。

- 单条事件的摊还成本与队列里已有的条数无关：不许每来一条重扫整个队列。
- 时间（验收机：本机 CPython、单进程单线程）：`06-scale` 的 `run` ≤ 5 秒，其余 `run` ≤ 2 秒，`report`
  ≤ 2 秒。
- 对拍（逐条可核）：`python backpressure.py run samples/scripts/<名>.txt var/<名>.txt` 与
  `samples/expected/<名>.txt` 逐字节相同。
- 门槛：`T` 行的内存峰值、关键丢失、吞吐满足 `samples/expected-metrics.txt` 该行。
- 确定性：同一条命令跑两遍逐字节相同，不读系统时钟。
- 测试：`python -m unittest discover -s tests` 全绿，只用标准库、只读 `samples/**`。

## 八、样例说明

六个名字：`01-steady` `02-burst` `03-overload` `04-priority` `05-lowfill` `06-scale`，脚本与期望同名
一一对应；括号里是 到达 / 入队 / 拒收 / 驱逐 / 关键 / 峰值字节 / 峰值条数 / 背压 / 吞吐。

| 样例 | 场景与关键结果 |
| --- | --- |
| `01-steady` | 平稳：每 80 毫秒两条，最深处 2 条，一条不丢（240 / 240 / 0 / 0 / 0 / 576 / 2 / 0 / 24.806） |
| `02-burst` | 突发洪峰：0.5 秒挤进 200 条，顶出一次背压，之后回升到滞回带里也不误报（256 / 81 / 175 / 12 / 4 / 16320 / 18 / 1 / 5.196） |
| `03-overload` | 长时间过载：一进场就顶到预算，背压从 420 压到 15375 毫秒（1500 / 347 / 1153 / 6 / 38 / 32768 / 9 / 1 / 22.064） |
| `04-priority` | 高等级密集：三轮背压里重要事件挤掉 49 条普通事件，关键一条不落（564 / 191 / 373 / 49 / 24 / 24576 / 54 / 3 / 14.115） |
| `05-lowfill` | 普通事件占满队列：条数先到顶、字节水位没到，同级新来的自己走，关键仍挤进 48 条的队（232 / 107 / 125 / 15 / 12 / 3840 / 48 / 0 / 20.354） |
| `06-scale` | 上万条事件：十段洪峰与恢复，队列在预算下反复起落，关键全送达（17600 / 6910 / 10690 / 0 / 320 / 126976 / 423 / 10 / 143.287） |

`samples/notes.md` 是现场记录（背景不是规格），冲突以本文件为准。
